# Codebase Overview

## 1) Django/Python Mental Model

| JS/TS concept here | Python/Django concept to compare |
|---|---|
| Worker `fetch` runtime generated by Flue/Vite | `asgi.py` or FastAPI bootstrap |
| Hono router in `src/app.ts` | Django `urls.py` plus middleware and views |
| Flue `ResearchAgent` | Stateful async service/orchestrator |
| React `App` component | Template, view context, and browser controller combined |
| TypeScript `type` | Type hint, `TypedDict`, or dataclass intent |
| Environment binding | Configured setting or injected service client |
| Wrangler migration | Django migration, but for Durable Object classes rather than database fields |
| Vitest | pytest |

The comparison is conceptual, not exact: React state lives in the browser, Flue state lives in a Durable Object, and Hono does not provide Django's ORM/admin stack.

## 2) System Context

The browser sends API and Flue requests to one Cloudflare Worker. Hono applies security and ownership checks, Flue resumes one durable research agent, Workers AI generates the answer, and enabled official MCP servers provide source evidence. See `src/app.ts` and `src/agents/research-agent.ts`.

External integrations:

- Workers AI binding `AI` for the selected curated model.
- AI Gateway configured by `AI_GATEWAY_ID`.
- Cloudflare Docs MCP at the registered or environment-overridden endpoint.
- AWS Knowledge MCP at the registered or environment-overridden endpoint.
- Cloudflare Static Assets binding `ASSETS` for the React build.

## 4) Runtime Traffic Flow

- Input: React sends selected model/source IDs to `POST /api/conversations`, then sends prompts through Flue routes (`frontend/src/App.tsx`).
- Orchestrator: Hono validates ownership and routes the signed ID to `ResearchAgent` (`src/app.ts`).
- Processing: the agent mounts its instruction/skill, calls Workers AI, and directly queries relevant enabled MCP tools (`src/agents/research-agent.ts`).
- Output: Flue persists and streams message parts; React renders text and a sanitized trace (`frontend/src/activity.ts`).

Detailed sequence:

1. Local storage is parsed as untrusted data.
2. The Worker creates/reuses a session cookie and signs `<model>.<source-mask>.<uuid>` with session-derived HMAC.
3. Middleware verifies token structure and signature for every durable route.
4. The agent decodes model/source configuration from the ID so restored threads cannot drift.
5. The agent must activate `research-planning` before substantive vendor research.
6. Flue stores the conversation in its generated Durable Object class.

## 5) Hosting + Infra

- `vite.config.ts` lets Flue scan the agent and lets Cloudflare build the Worker.
- `frontend/vite.config.ts` builds React separately into `dist-web/` and proxies local `/api` traffic to port 5173.
- `scripts/prepare-deploy.mjs` adds Static Assets settings to Flue's generated Wrangler snapshot.
- `wrangler.jsonc` defines public variables, Workers AI, assets, Durable Object binding/migrations, logs, and traces.
- `npm run deploy` is the supported production path (`package.json`).

The split build is intentional: Flue produces the Worker manifest while frontend Vite produces static assets.

## 6) Security + Auth

- There is no account login. Isolation is an anonymous HttpOnly cookie plus a session-bound signed conversation ID (`src/lib/session.ts`).
- HMAC verification occurs before Flue can read, stream, mutate, or cancel a conversation (`src/app.ts`).
- Model and MCP IDs use explicit runtime allowlists (`src/lib/registry.ts`).
- MCP tokens are optional Worker secrets named `CF_DOCS_VECTORIZE_MCP_TOKEN` and `AWS_KNOWLEDGE_MCP_TOKEN`.
- Security headers block MIME sniffing and browser camera, microphone, and geolocation use (`src/app.ts`).

This is appropriate for browser-session separation, not confidential multi-user identity enforcement.

## 7) API Surface

- `GET /api/health`: routing readiness.
- `POST /api/conversations`: validated signed-thread creation.
- `/api/agents/research/:conversationId/*`: Flue's durable conversation protocol behind ownership middleware.
- `GET|HEAD /*`: static file and SPA fallback.

Flue owns the exact subroutes under the agent prefix; application code owns the prefix and security gate.

## 8) Data Model/Storage

Server-side:

- Flue's `FlueResearchAgentAgent` SQLite Durable Object stores durable conversation state (`wrangler.jsonc`).
- No D1, KV, R2, queue, or application ORM is configured.

Browser-side:

- `tech_docs_flue_conversation`: current pointer.
- `tech_docs_flue_conversations`: up to 30 recent pointers.
- `tech_docs_flue_model`: preferred model.
- `tech_docs_flue_mcp_servers`: preferred source IDs.

Deleting a browser pointer does not delete server-side Flue history (`frontend/src/App.tsx`).

## 9) JS/TS Syntax Notes for Python Developers

- `import`/`export` are Python module imports and public names.
- `async function` returning `Promise<T>` is `async def` returning an awaited result.
- `type` describes compile-time shape; runtime guards such as `isModelId()` play the Pydantic/serializer role for external data.
- `null` means explicit no-value; `undefined` usually means omitted or not initialized. Both resemble `None` in different circumstances.
- `value?.field` is safe optional access.
- `value ?? fallback` uses the fallback only for `null`/`undefined`, not for `0`, `false`, or an empty string.
- `array.map`, `filter`, and `find` compare to comprehensions, `filter`, and `next(...)`.
- Object destructuring such as `{ id }` extracts by property name, similar to reading a dictionary key into a local variable.
- Union literals such as `'running' | 'complete'` compare to Python `Literal` constraints.

## 10) Failure and Fallback Paths

- Invalid JSON or unknown model/source IDs: `POST /api/conversations` returns `400`.
- Missing/malformed/wrong-session token: ownership middleware returns `401`.
- Missing MCP override: the agent falls back to the public registry URL; MCP connections are optional so the model can report an evidence gap.
- Prompt send failure: React restores the prompt and shows an error.
- Conversation creation failure: React keeps the current UI and shows an error.
- Empty local history after deletion: React creates a fresh conversation.
- Unknown frontend path: Static Assets serves the SPA index.
- Build/deploy drift: `npm run deploy` rebuilds both outputs and patches the generated deployment config before Wrangler runs.
