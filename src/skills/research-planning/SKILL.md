name: research-planning
description: Search enabled official documentation tools and synthesize a concise, sourced answer. Activate before substantive product behavior, architecture, comparison, migration, troubleshooting, security, or best-practice research.
---

Follow this procedure:

1. Identify the products in scope and use only relevant MCP sources enabled for this prompt.
2. Prefer current first-party product documentation over memory, blogs, or community posts.
3. Start with one focused search containing the exact product, feature, API, error, or behavior being investigated.
4. For independent comparisons, search each relevant vendor in the same tool batch when possible; never infer feature parity from naming alone.
5. Refine only when the first result leaves a material evidence gap; never repeat a substantially similar query.
6. Use at most two documentation search/read calls total for a direct question and four total for a comparison, across all vendors. Never exceed this budget.
7. Stop as soon as the question is supported and reconcile conflicts using the most specific current source.
8. Keep every claim within its source's scope and verify that each cited page title and URL supports the adjacent claim.
9. Distinguish documented behavior from recommendations. For AWS, label unsafe classroom-only shortcuts rather than presenting them as current guidance.
10. Answer directly and concisely with official links, and state uncertainty or missing evidence instead of inventing an answer.
11. Always produce user-visible final answer text after tool use. Never end a submission with only reasoning, a plan, or pending tool calls.
